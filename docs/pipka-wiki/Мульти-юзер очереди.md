# Мульти-юзер очереди

С 17 августа 2026 поиск и скоринг распределяются между пользователями **справедливо**: ни один профиль не может съесть лимиты источников или AI-квоту остальных. До этого запросы всех пользователей сливались в общий список, и источники с капами (JobSpy top-N, Adzuna combo-cap) обслуживали в основном первого пользователя.

Файл: `app/services/user_scope_service.py`. Используется в `scheduler_service.py`, `embedding_service.py`, `ops_service.py`.

## План поиска на пользователя

`build_user_search_plans(users)` → по одному `UserSearchPlan` на каждого активного пользователя с настроенным профилем: его target titles (в порядке профиля = приоритет) и **явные** ISO-коды стран (`profile_target_countries`).

## Справедливое слияние

`merge_user_search_plans(plans, start_offset)`:

- планы **ротируются** на `start_offset` — в каждом скане первым идёт другой пользователь;
- titles и страны сливаются **round-robin** (1-й title первого пользователя, 1-й второго, 2-й первого…) с дедупом;
- сохраняются точные связки «страна ↔ titles» каждого пользователя, чтобы чужие страны не искались по твоим титулам.

Смещение `_search_round_robin_offset` увеличивается после каждого скана.

## Backfill

`_backfill_score` обходит пользователей в порядке, ротируемом через `_backfill_round_robin_offset` (`rotate_items`), — при ограниченном `BACKFILL_AI_JOBS_PER_RUN` очередь каждого пользователя получает свою долю.

## Scope для эмбеддингов и Ops

`active_target_scope(session)` — id активных профилей + объединение их явных стран. По нему [[Поиск и индексация]] ограничивает индексацию эмбеддингов целевыми странами, а [[Ops панель]] считает очередь скоринга только по релевантным вакансиям.
