# Поиск и индексация

Слой retrieval перед AI-скорингом. Цель — быстро находить релевантные вакансии в базе и постепенно уменьшать количество дорогих LLM-вызовов.

## Full-text search

Миграция: `alembic/versions/0004_search_embeddings.py`.

В `jobs` добавлена generated-колонка `search_vector`:

- `title` — вес `A`
- `company_name` — вес `A`
- `description` — вес `B`

Индекс:

```sql
CREATE INDEX ix_jobs_search_vector
ON jobs USING gin (search_vector);
```

`GET /api/jobs?search=...` на PostgreSQL использует:

```sql
search_vector @@ websearch_to_tsquery('simple', :term)
```

Для SQLite/dev остаётся fallback через `ILIKE`.

## Semantic indexing

Миграция включает `pgvector`:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

Docker DB image переключён на `pgvector/pgvector:pg16`, иначе стандартный `postgres:16-alpine` не содержит extension `vector`.

Колонки:

- `jobs.embedding vector(2048)`
- `jobs.embedding_model`
- `jobs.embedding_updated_at`
- `user_profiles.embedding vector(2048)`
- `user_profiles.embedding_model`
- `user_profiles.embedding_updated_at`
- `user_profiles.embedding_profile_hash`

Для 2048-мерного `vector` pgvector не поддерживает HNSW (лимит HNSW — 2000
dimensions). Поэтому HNSW-индексы из предыдущей 768-мерной схемы удалены;
semantic retrieval использует точное cosine-сравнение. Исторический архив
намеренно не индексируется, чтобы линейный запрос оставался ограниченным
актуальной выборкой.

## Embedding backend

Файл: `app/services/embedding_service.py`.

Основной backend: NVIDIA Nemotron через NVIDIA API. Gemini остаётся
поддерживаемым альтернативным provider через `google-genai`.

Настройки:

| Env | Default |
|-----|---------|
| `EMBEDDING_ENABLED` | `true` |
| `EMBEDDING_PROVIDER` | `nvidia` |
| `EMBEDDING_MODEL` | `nvidia/nemotron-3-embed-1b` |
| `EMBEDDING_DIMENSION` | `2048` |
| `EMBEDDING_JOBS_PER_RUN` | `70` |
| `EMBEDDING_PROFILES_PER_RUN` | `20` |
| `EMBEDDING_INDEX_INTERVAL_HOURS` | `2` |
| `EMBEDDING_BURST_INTERVAL_MINUTES` | `30` |
| `EMBEDDING_BURST_QUEUE_THRESHOLD` | `100` |
| `EMBEDDING_INDEX_MAX_AGE_DAYS` | `31` |
| `EMBEDDING_INDEX_COUNTRY` | legacy; active worker uses union of `preferred_countries` |
| `EMBEDDING_INDEX_MIN_SCORE` | `60` |
| `SEMANTIC_SEARCH_LIMIT` | `500` |

Если нет ключа для выбранного provider или используется не-PostgreSQL БД,
сервис делает безопасный no-op.

## Scheduler

Job: `embed_index`.

Расписание: обычный запуск каждые `EMBEDDING_INDEX_INTERVAL_HOURS`, плюс
startup run через 90 секунд. Для `EMBEDDING_PROVIDER=nvidia` действует
отдельный burst-worker: каждые 30 минут он сначала считает scoped очередь и
берёт очередной пакет только если в ней строго больше 100 вакансий. Burst не
трогает profile embeddings; они остаются задачей обычного запуска.

Что делает:

1. Строит объединение `preferred_countries` всех активных пользователей.
2. Берёт только вакансии этих рынков без `jobs.embedding`, опубликованные/собранные не более 31 дня назад, со статусом `active`/unknown и хотя бы одной оценкой ≥60 от активного user.
3. Строит текст: title, company, location, country, description.
4. Получает embedding с task type `retrieval_document` и обновляет `jobs.embedding`.
5. Берёт только активные профили, у которых `embedding_profile_hash` не совпадает с текущим `profile_hash`.
6. Получает embedding профиля с task type `retrieval_query` и обновляет `user_profiles.embedding`.

События пишутся в `ops_events` как `embedding_index`.

## Semantic API

`GET /api/jobs?semantic=1` ограничивает выборку top-N вакансиями по близости к embedding профиля:

```sql
ORDER BY jobs.embedding <=> user_profiles.embedding
```

`include_closed=0` продолжает скрывать вакансии с `url_status='closed'`.

## Что это даёт

- Быстрый текстовый поиск без `ILIKE '%term%'` по всей таблице.
- Персональный semantic retrieval по резюме/профилю.
- Основа для следующего шага: передавать в Gemini/NVIDIA только top-N кандидатов после vector pre-rank.
