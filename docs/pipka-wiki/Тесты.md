# Тесты

Покрытие — набор unit- и integration-проверок, но оно не заменяет полный end-to-end прогон production-потока. На 23.09.2026 последний зафиксированный запуск: **231 passed**. Список тестов расширен: проверяются API, пользовательские настройки/изоляция, Gemini quota/fallback, scoring и очередь. Этот результат относится к состоянию кода на момент запуска и не гарантирует, что все тесты после последующих изменений проходят.

## Стек

- `pytest>=8.0`
- `pytest-asyncio>=0.24`
- `ruff>=0.8` (линтер)

Все три в `[project.optional-dependencies].dev` — устанавливаются `pip install -e '.[dev]'`.

## Что покрыто

`tests/` — pre-filter из `app/scoring/rules.py` (см. [[Скоринг]]), scoring providers и отдельные API/пользовательские потоки:

| Тест | Проверяет |
|------|-----------|
| `test_hard_reject_junior` | "Junior Procurement Analyst" → отвергается (`bucket="low"`) |
| `test_hard_reject_foreign_language` | "fluent french required" → low |
| `test_user_exclusions` | `excluded_keywords=["amazon"]` + Amazon в description → low |
| `test_english_only_filter_fail` | Профиль `english_only=True` + чисто немецкий title → low |
| `test_english_only_filter_pass` | English-friendly description → проходит |
| `test_domain_check_fail` | "Marketing Director" → low (не та функция) |
| `test_director_passes` | "Director Supply Chain" + supply chain в description → bucket="high" |
| ... | Также см. `tests/test_gemini_quota.py`, `tests/test_profile_preferences.py` и остальные тестовые модули |

Запуск:

```bash
pip install -e '.[dev]'
pytest tests/ -v
```

## Оставшиеся пробелы (пункты для [[Roadmap]])

- **Полное API-покрытие:** не все endpoints проверяются на авторизацию, tenant isolation и одинаковую форму ошибок.
- **Production-provider smoke tests:** локальные тесты не подтверждают текущую доступность Gemini/NVIDIA и лимиты ключей.
- **Тесты на дедуп** (`is_fuzzy_duplicate`, `_locations_conflict`).
- **Тесты на `compute_profile_hash`** — стабильность, нечувствительность к whitespace.
- **Тесты на UPSERT-логику** — что mismatched rows перезаписываются, NULL не трогаются.

## CI

`pyproject.toml` содержит конфиг ruff/pytest; CI остаётся неполным/не является гарантией для каждого деплоя. Перед выводом о текущей зелёности повторно запускайте `pytest tests/ -q` на соответствующем commit. См. [[Roadmap]].

## Smoke check на проде

После каждого деплоя минимальная триада:

```bash
# 1. Контейнер поднялся
docker logs pipka-app-1 --since 90s | grep -E 'Bot is running|Traceback|alembic'

# 2. Health endpoint жив
curl https://pipka.net/health   # → {"status":"ok","service":"pipka"}

# 3. Свежий success в ops_events
docker exec pipka-db-1 psql -U pipka -d pipka -c \
  "SELECT created_at, event_type, status FROM ops_events
   WHERE created_at > now() - interval '30 minutes'
   ORDER BY created_at DESC LIMIT 5;"
```
