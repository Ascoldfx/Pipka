# Биллинг и кредиты

Кредитная модель монетизации: AI-оценка вакансий в реальном времени расходует кредиты пользователя, пополнение — через криптоплатёжный шлюз Cryptomus. Введена 7 августа 2026 (migration `0011_user_billing_and_transactions`).

Файлы: `app/services/billing_service.py`, `app/api/billing.py`, модель `PaymentTransaction` в `app/models/user.py`.

## Баланс пользователя

Колонки в `users` ([[База данных]]):

| Колонка | Дефолт | Смысл |
|---|---|---|
| `credits` | `50` | Текущий баланс (trial-кредиты при регистрации, `DEFAULT_USER_TRIAL_CREDITS`) |
| `total_credits_purchased` | `0` | Сумма всех купленных кредитов |
| `subscription_tier` | `free` | Тариф (пока информационное поле) |

Баланс видно в дашборде и в Telegram-боте (`/settings` → «💰 Кредиты»).

## Списание

Списание встроено в `_score_and_notify` (`app/services/scheduler_service.py`) — real-time путь после скана:

- **1 кредит = 1 AI-оценённая вакансия.** Списывается `min(credits, число оценок)` после батча.
- При `credits <= 0` AI-скоринг для пользователя пропускается, в сводку скана пишется `error: credits_exhausted`.
- **Админы (`role == "admin"`) не ограничены и не списываются** (с 8 августа 2026).
- Backfill ([[Скоринг]]) кредиты **не** расходует — это фоновая инфраструктурная работа.

Хелпер `deduct_user_credits()` (атомарный `UPDATE … WHERE credits >= N`) в `billing_service.py` существует, но **нигде не вызывается** — списание сделано инлайн в шедулере. Кандидат на рефакторинг, см. [[Roadmap]].

## Платёжный поток (Cryptomus)

1. `POST /api/billing/checkout {tier}` → создаётся `payment_transactions` со статусом `pending`, запрашивается invoice у `https://api.cryptomus.com/v1/payment`, клиенту отдаётся `payment_url`.
2. Пользователь платит на стороне Cryptomus.
3. Cryptomus шлёт `POST /api/webhooks/crypto`:
   - подпись проверяется `verify_cryptomus_signature()` (MD5 от тела + `CRYPTOMUS_PAYMENT_KEY`) → иначе `400 Invalid signature`;
   - статусы `paid` / `paid_over` → `fulfill_payment_transaction()` начисляет кредиты;
   - остальные статусы → `{"status": "ignored"}`.
4. `fulfill_payment_transaction` **идемпотентен**: повторный вебхук по уже `paid` транзакции ничего не начисляет.

Без `CRYPTOMUS_MERCHANT_ID` + `CRYPTOMUS_PAYMENT_KEY` оплата отключена: checkout и вебхук отвечают `503`.

## Sandbox

`POST /api/billing/test-fulfill/{tx_id}` — ручное «проведение» транзакции для разработки. Доступен **только** когда `BILLING_TEST_MODE=true` **и** live-ключи Cryptomus не заданы (`sandbox_billing_enabled()`); иначе `404`. На production с живыми ключами эндпоинт физически недоступен.

## Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/billing/balance` | Баланс, история транзакций, каталог пакетов |
| POST | `/api/billing/checkout` | Создать invoice (`starter` / `pro`) |
| POST | `/api/webhooks/crypto` | Вебхук Cryptomus (подпись, без CSRF-сессии) |
| POST | `/api/billing/test-fulfill/{tx_id}` | Sandbox-проведение |
